# Юность

Веб-приложение педагогического отряда «Юность».

Автор учебного проекта: Гущина Алина Артемовна, ПР-24.103.

## Текущий этап

Начальный фронтенд внутри проекта ASP.NET Core. Это исходный код будущего приложения: его можно редактировать, запускать и хранить в GitHub. SQL Server, авторизация и хранение пользовательских данных ещё не подключены.

Работают:

- Главная, «О нас», блог с архивными материалами, услуги.
- Девять услуг с фотографиями, фильтром и ссылками на Telegram `@DOBLEST_78`.
- Магазин одежды для Фыр-Фырыча, фильтрация и визуальная примерка шести вещей.
- Переходы между разделами, мобильное меню, закрытие примерки по Escape.
- Формы входа и вступления с проверкой обязательных полей. Они показывают, что сервис ещё не открыт, и не отправляют персональные данные.
- Сервер ASP.NET Core раздаёт интерфейс и отвечает на `GET /api/health`.
- Панель управления: переключение разделов, редактор новости и мероприятия, выбор изображений, живой предпросмотр, время публикации, срок показа, место, число участников и награда в яблоках.
- Экраны команды и прав, подтверждения участия, начисления яблок и настройки очистки — пока на уровне интерфейса, без записи в базу.

Пока не реализованы:

- SQL Server и таблицы, ER-диаграмма.
- Учётные записи, роли, модерация заявок и личный кабинет после входа.
- Запись на события, начисление яблок, покупка и сохранение одежды.
- Серверное сохранение публикаций и черновиков, выдача ролей, автоматическая очистка и размещение на сервере.

Баланс и покупки не имитируются в localStorage. Примерка — только визуальный просмотр. Личные разделы показывают состояние для гостя. Цены игровых вещей взяты из макета и пока являются проектными.

## Быстрый просмотр

1. Распакуй архив полностью.
2. Открой `preview.cmd` либо `src/Yunost.Web/wwwroot/index.html`.
3. Сайт откроется в браузере. Установка программ для этого просмотра не нужна.

Для просмотра редактора и новых экранов нажми **«Управление сайтом»** внизу страницы. Затем **«Создать публикацию»**. Можно вводить текст, прикреплять фото и смотреть результат. Данные формы временные: после ухода со страницы они не сохраняются, пока не подключён сервер.

Это только просмотр интерфейса. Для работы сервера используй следующий способ.

## Запуск проекта

На обоих твоих устройствах установи **.NET 10 SDK**:
https://dotnet.microsoft.com/download/dotnet/10.0

Выбери SDK для своей Windows. Нужен именно SDK, не только Runtime.

Затем открой `start.cmd`. Когда в окне появится `Now listening on: http://localhost:5080`, открой этот адрес в браузере. Пока работаешь с сайтом, оставляй окно запуска открытым. Для остановки нажми Ctrl+C.

То же самое из терминала в папке проекта:

```powershell
dotnet run --project src/Yunost.Web
```

Проверка сборки:

```powershell
dotnet build Yunost.slnx
```

В проекте нет npm-зависимостей. HTML, CSS и JavaScript не требуют отдельной сборки. На текущем этапе не нужны Docker или локальная база данных.

## Работа на двух устройствах

Один проект — один GitHub-репозиторий — две локальные копии. Не создавай отдельный репозиторий для ноутбука.

Перед работой: **Fetch origin → Pull origin**, если есть изменения.

После работы: сохранить файлы → **Commit to main → Push origin**.

Подробная инструкция: [Работа на двух устройствах](docs/WORK_ON_TWO_DEVICES.md).

GitHub переносит код. После подключения базы рабочие данные будут храниться на сервере SQL Server. Они не будут переноситься коммитами.

## Материалы и ограничения

Сохранены исходный фон, фотографии отряда, новый логотип с воздушным змеем и Фыр-Фырыч. Фотографии услуг — ранее подготовленные иллюстрации; сайт не выдаёт их за портфолио реальных мероприятий. Фотографии оптимизированы для веба в WebP. Архивные материалы блога не выданы за новые события.

Сервисные заявки сейчас доступны через ссылку на Telegram. Нажатие открывает переписку, но не отправляет сообщение автоматически.

На этапе подключения регистрации нужно добавить согласованный текст обработки персональных данных, серверную валидацию и защиту запросов. Текущая сборка предназначена для локальной разработки, не для приёма реальных пользовательских данных.

Секретов в исходниках нет. `.gitignore` исключает локальные секреты, сертификаты, файлы SQL Server и резервные копии БД. Сами исключения не заменяют проверку списка файлов перед коммитом.
